# Tài liệu tích hợp FE - Luồng đăng ký tài khoản bác sĩ bằng invitation link

## 1\. Tổng quan flow

Backend đã có chức năng Admin gửi email mời đăng ký tài khoản bác sĩ.

Flow tổng quát:

- Admin nhập email bác sĩ trong trang quản trị.
- Backend tạo invitation token.
- Backend gửi email qua Brevo.
- Email chứa link:

/register-doctor?token=...

- Người nhận bấm link.
- FE mở trang /register-doctor.
- FE lấy token từ URL.
- FE gọi API validate token.
- Nếu token hợp lệ thì hiển thị form đăng ký bác sĩ.
- Nếu token hết hạn, đã dùng hoặc sai thì hiển thị lỗi.
- Người dùng nhập form và submit.
- FE gọi API register doctor bằng token.
- Backend tạo tài khoản role Doctor và tạo hoặc liên kết Doctor profile.
- Register thành công thì FE điều hướng về trang login.

Link invitation hiện có hạn trong **2 phút**.

## 2\. URL FE cần có

FE cần tạo page:

/register-doctor

Page này nhận token từ query string:

/register-doctor?token=abcxyz

Backend config hiện đang dùng:

"Frontend": {  
"BaseUrl": "<https://sep-490-fe-medical-ai-assistant.vercel.app>"  
}

Backend sẽ tự ghép link email thành:

<https://sep-490-fe-medical-ai-assistant.vercel.app/register-doctor?token=>...

## 3\. API validate invitation token

Khi page /register-doctor load, FE cần lấy token:

const params = new URLSearchParams(window.location.search);  
const token = params.get("token");

Sau đó gọi API:

GET /api/doctor-invitations/validate?token={token}

Endpoint này không cần login.

### Response khi token hợp lệ

{  
"success": true,  
"message": "Invitation link is valid.",  
"data": {  
"isValid": true,  
"email": "<doctor@example.com>",  
"expiresAt": "2026-06-11T10:00:00Z",  
"doctorId": null,  
"isLinkedToExistingDoctorProfile": false,  
"doctorName": null,  
"message": "Invitation link is valid."  
}  
}

### Response khi token gắn với Doctor profile cũ

{  
"success": true,  
"message": "Invitation link is valid.",  
"data": {  
"isValid": true,  
"email": "<doctor@example.com>",  
"expiresAt": "2026-06-11T10:00:00Z",  
"doctorId": "doctor-profile-id",  
"isLinkedToExistingDoctorProfile": true,  
"doctorName": "Dr. Nguyen Van A",  
"message": "Invitation link is valid."  
}  
}

### Response khi token không hợp lệ hoặc hết hạn

{  
"success": true,  
"message": "Invitation link has expired.",  
"data": {  
"isValid": false,  
"email": null,  
"expiresAt": null,  
"doctorId": null,  
"isLinkedToExistingDoctorProfile": false,  
"doctorName": null,  
"message": "Invitation link has expired."  
}  
}

FE xử lý:

- Nếu data.isValid === true: hiển thị form đăng ký.
- Nếu data.isValid === false: hiển thị màn hình lỗi.

Gợi ý message:

Link đăng ký không hợp lệ hoặc đã hết hạn. Vui lòng liên hệ quản trị viên để nhận lời mời mới.

## 4\. Có 2 trường hợp đăng ký bác sĩ

### Trường hợp 1: Bác sĩ mới chưa có Doctor profile

Dấu hiệu từ API validate:

{  
"isLinkedToExistingDoctorProfile": false,  
"doctorId": null  
}

FE cần hiển thị form đầy đủ:

Email  
Full name  
Password  
Confirm password  
Phone number  
Facility department  
Department role  
Qualification  
Years of experience

Email lấy từ response validate và nên để read-only.

### Trường hợp 2: Bác sĩ đã có Doctor profile nhưng chưa có tài khoản login

Dấu hiệu từ API validate:

{  
"isLinkedToExistingDoctorProfile": true,  
"doctorId": "doctor-profile-id",  
"doctorName": "Dr. Nguyen Van A"  
}

FE có thể hiển thị thông tin profile cũ và chỉ yêu cầu user tạo tài khoản login.

Form tối thiểu:

Email  
Full name  
Password  
Confirm password  
Phone number

Không bắt buộc FE gửi facilityDepartmentId và departmentRole trong trường hợp này, vì Doctor profile cũ đã có sẵn thông tin chuyên môn.

## 5\. API register doctor bằng invitation token

Khi user submit form, FE gọi:

POST /api/doctor-invitations/register

Endpoint này không cần login.

### Body cho bác sĩ mới chưa có Doctor profile

{  
"token": "token-from-url",  
"fullName": "Doctor Test",  
"password": "Password123!",  
"phoneNumber": "0900000000",  
"facilityDepartmentId": "facility-department-id",  
"departmentRole": 0,  
"qualification": "General Doctor",  
"yearsOfExperience": 3  
}

Trong đó:

token: lấy từ URL /register-doctor?token=...  
fullName: tên bác sĩ  
password: mật khẩu tài khoản  
phoneNumber: số điện thoại  
facilityDepartmentId: khoa/phòng ban tại cơ sở y tế  
departmentRole: vai trò trong khoa  
qualification: chuyên môn/bằng cấp  
yearsOfExperience: số năm kinh nghiệm

### Body cho bác sĩ đã có Doctor profile cũ

{  
"token": "token-from-url",  
"fullName": "Doctor Test",  
"password": "Password123!",  
"phoneNumber": "0900000000"  
}

Không cần gửi:

facilityDepartmentId  
departmentRole  
qualification  
yearsOfExperience

Nếu FE vẫn gửi các field này thì backend có thể cập nhật nếu hợp lệ, nhưng với MVP nên tránh gửi để không ghi đè dữ liệu profile cũ.

## 6\. Response register thành công

{  
"success": true,  
"message": "Doctor account registered successfully.",  
"data": {  
"userId": "user-id",  
"doctorId": "doctor-id",  
"email": "<doctor@example.com>",  
"fullName": "Doctor Test",  
"role": "Doctor",  
"message": "Doctor account registered successfully."  
}  
}

FE xử lý:

Hiển thị đăng ký thành công.  
Redirect sang trang login.

Gợi ý message:

Đăng ký tài khoản bác sĩ thành công. Vui lòng đăng nhập để tiếp tục.

## 7\. Response register thất bại thường gặp

### Token hết hạn

{  
"success": false,  
"message": "Register doctor failed.",  
"errors": \[  
"Invitation link has expired."  
\]  
}

### Token đã dùng

{  
"success": false,  
"message": "Register doctor failed.",  
"errors": \[  
"Invitation link has already been used."  
\]  
}

### Email đã có tài khoản

{  
"success": false,  
"message": "Register doctor failed.",  
"errors": \[  
"This email is already registered."  
\]  
}

### Password không đạt rule

{  
"success": false,  
"message": "Register doctor failed.",  
"errors": \[  
"Passwords must be at least 8 characters.",  
"Passwords must have at least one non alphanumeric character.",  
"Passwords must have at least one digit.",  
"Passwords must have at least one uppercase."  
\]  
}

FE nên hiển thị các lỗi trong errors.

## 8\. Password rule

Backend đang dùng Identity password rule:

Ít nhất 8 ký tự  
Có chữ thường  
Có chữ hoa  
Có số  
Có ký tự đặc biệt

Ví dụ password hợp lệ:

Password123!

## 9\. Department role

Nếu FE cần chọn departmentRole, dùng giá trị enum dạng number.

Gợi ý mapping:

0 = Staff  
1 = DeputyHead  
2 = Head  
3 = LeadingExpert  
4 = Consultant

Nếu BE response Swagger thể hiện enum dạng string thì FE có thể gửi string theo schema, nhưng hiện nên ưu tiên number theo enum backend.

## 10\. Lấy danh sách FacilityDepartment

Form đăng ký doctor mới cần facilityDepartmentId.

FE có thể lấy thông qua API cơ sở y tế/khoa hiện có trong hệ thống. Nếu hiện chưa có API riêng cho FacilityDepartment, FE có thể lấy từ detail/list medical facilities nếu response có departments.

Cần chọn đúng facilityDepartmentId, không phải chỉ departmentId.

## 11\. FE validation đề xuất

Trước khi gọi register, FE nên kiểm tra:

Token có tồn tại không  
Full name không rỗng  
Password và confirm password trùng nhau  
Password đạt rule cơ bản  
Phone number hợp lệ nếu có nhập  
Nếu isLinkedToExistingDoctorProfile = false:  
facilityDepartmentId bắt buộc  
departmentRole bắt buộc

Nếu isLinkedToExistingDoctorProfile = true, không bắt buộc facilityDepartmentId và departmentRole.

## 12\. UX đề xuất cho trang register doctor

### Khi đang validate token

Đang kiểm tra lời mời đăng ký...

### Token invalid/expired

Link đăng ký đã hết hạn hoặc không hợp lệ.  
Vui lòng liên hệ quản trị viên để nhận lời mời mới.

### Token valid, doctor mới

Hoàn tất đăng ký tài khoản bác sĩ  
Email: <doctor@example.com>

Hiển thị form đầy đủ.

### Token valid, linked existing profile

Hoàn tất tạo tài khoản đăng nhập cho hồ sơ bác sĩ  
Email: <doctor@example.com>  
Hồ sơ: Dr. Nguyen Van A

Hiển thị form tối giản.

### Register success

Đăng ký thành công. Vui lòng đăng nhập.

## 13\. Lưu ý bảo mật

FE không cho user sửa email.

Email phải lấy từ API validate và chỉ hiển thị read-only.

Khi register, FE không gửi email lên backend. Backend tự lấy email từ invitation token.

Không lưu token lâu dài trong localStorage. Chỉ đọc token từ URL và gửi trong request register.

## 14\. Test FE nhanh

Case 1: Doctor mới chưa có profile

1\. Admin gọi POST /api/admin/doctor-invitations với email.  
2\. Mở email.  
3\. Click link /register-doctor?token=...  
4\. FE validate token.  
5\. FE hiển thị form đầy đủ.  
6\. Submit form.  
7\. Kỳ vọng tạo user role Doctor + tạo Doctor profile mới.  
8\. Redirect login.

Case 2: Doctor đã có profile cũ

1\. Admin tạo Doctor profile trước, profile này có UserId = null.  
2\. Admin gọi POST /api/admin/doctor-invitations với email + doctorId.  
3\. Mở email.  
4\. Click link /register-doctor?token=...  
5\. FE validate token.  
6\. FE thấy isLinkedToExistingDoctorProfile = true.  
7\. FE hiển thị form tối giản.  
8\. Submit token + fullName + password + phoneNumber.  
9\. Kỳ vọng tạo user role Doctor và gắn UserId vào Doctor profile cũ.  
10\. Không tạo Doctor profile mới.

Case 3: Token hết hạn

1\. Admin gửi invitation.  
2\. Đợi hơn 2 phút.  
3\. Mở link.  
4\. FE validate token.  
5\. Kỳ vọng isValid = false.

Case 4: Dùng lại token

1\. Register thành công một lần.  
2\. Mở lại link cũ.  
3\. FE validate token.  
4\. Kỳ vọng invalid hoặc register fail.
